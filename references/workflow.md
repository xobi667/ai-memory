# 任务选择、预设与交接检查

以下命令由 AI 从实际技能目录运行：`python scripts/ai_memory.py <命令>`，用户不必记住命令。除 `status` 外，项目须已有 `.ai-memory/project.json` 和有实际授权依据的任务范围；这些命令不创建业务骨架，不执行项目验证。

## 一眼查看记录状态

`status --root <项目>` 默认显示中文摘要，`--json` 返回机器格式；可用 `--task`，或配对的 `--client`、`--session` 指定已有任务。摘要显示保存的任务、记录中的验证声明、下一步来源、交接缺口和文档复核提示。它只观察已保存的材料，不会补记聊天、运行测试或宣布业务完成。

尚未启用结构化记忆的项目属于正常情况，可沿用一份简短交接文档；不必为了查看状态创建整套目录。多任务无法唯一选择、读取失败、扫描或输出被截断时，按诊断补读或指定任务，不能把摘要当作全量核验。轻量交接的实际状态直接从现有交接文档读取，脚本不凭文件存在推断已完成。

## 项目记录预设

先读 `preset --root <项目>`。没有保存过时返回默认建议，不生成文件。新任务结合实际目标、影响面和已有预设选择最少充分的记录；用户已经明确要求记录当前任务时，依据该指令用 `scope` 保存范围，不为档位再问一遍。同任务继续沿用有效确认。未知边界影响执行、超出已有授权或用户明确要求每任务先问时，再集中澄清。

经确认需要调整预设时，将下列 JSON 保存到请求文件：

```json
{
  "detail": "small",
  "modules": ["project"],
  "record_fields": ["changed", "verification", "next"],
  "notes": "局部改动优先简记，跨模块任务按实际影响升级档位。"
}
```

运行 `preset --root <项目> --file <请求.json> --confirmed`，建议保存到 `.ai-memory/presets.json`。支持 `small / standard / major`、模块和受支持的记录字段；上限 32 KiB。`--confirmed` 仍是调用者声明，不是独立审批凭证。预设不修改任何现有 scope，也不提供跨任务永久授权。范围摘要须注明真实指令和采用的建议项，不能把 AI 选择写成用户原话；经验仍不能自动升级为长期规则。

## 会话选择任务

```text
bind --root <项目> --task implement-search --client codex --session <真实会话ID>
resume --root <项目> --client codex --session <真实会话ID>
unbind --root <项目> --client codex --session <真实会话ID>
```

`client` 可用 `codex`、`claude`、`cursor` 或其他稳定客户端标识；ID 使用英文字母、数字、下划线、短横线。session 必须来自宿主或明确指定的可靠会话标识，不根据聊天内容或当前时间生成。两个客户端使用相同 session 字符串仍是两个绑定。

绑定仅保存项目身份、client、session 和 task ID；文件名由 client+session 的 SHA-256 生成，不将 session 直接拼入路径。绑定不复制目标、计划状态或确认权限。同一会话再次 `bind` 明确切换任务，其他会话不受影响。

任务选择顺序：**显式 `--task` → 有效会话绑定 → 唯一活动任务**。无效绑定立即报告，不回退到另一个任务；需要人工核对后重新绑定或解除绑定。显式任务或有效绑定可指向暂停／完成任务，输出会提醒其状态，读取不自动重新激活任务。

自动选择最多检查 128 个范围目录条目；扫描不完整、无效范围、未知状态或多个活动任务时不猜测。显式任务和有效绑定直接读取指定 scope，不受扫描数量限制。旧超限 scope 给出文件路径，先人工读取并精简，不把它当作不存在。没有可靠 session 的宿主继续显式选择任务。

## 唯一的任务状态来源

```text
task-status --root <项目> --task implement-search
task-status --root <项目> --task implement-search --status paused
```

支持 `active / paused / completed`，无法可靠读取时返回 `unknown` 和诊断。状态更新不增加 scope revision，不改变范围确认、目标或授权时间。

- 有 plan 的任务从登记的唯一计划读取状态。内置计划采用独立一行 `<!-- ai-memory-task-status: active -->`。状态命令只更新这一处；没有状态标记时，明确执行 `--status` 会补入标记。
- 无 plan 的 small 任务使用 scope 的 `task_status`，旧 small 范围缺少该字段时按 active 处理，不强迫创建计划。standard／major 缺少计划时状态未知，须登记唯一计划。
- 计划缺失、过大、标记重复或无法解析时不回退到 scope 的状态；代码围栏中的示例不作状态来源。机器读取计划上限 128 KiB，超过时按需拆分后再核对。

已有框架用自己的字段时，可在 `.ai-memory/status-mappings.json` 登记精确映射，保留原计划名称及字段：

```json
{
  "schema_version": 1,
  "project_id": "从本项目 project.json 读取的 UUID",
  "tasks": {
    "implement-search": {
      "field": "状态",
      "values": {"active": "进行中", "paused": "暂停", "completed": "已完成"}
    }
  }
}
```

此配置只描述怎么读取 scope.plan 的同一份计划，不保存第二份任务状态。支持单行 `状态：进行中`、`- 状态：进行中` 和 `status: working` 形式，包括前置 YAML 中的简单单行字段；字段必须唯一，三个状态值必须不同。不支持任意 YAML、表达式、嵌套字段或执行回调。映射与内置标记同时存在会报告冲突，先人工确定唯一来源，不能靠扫描顺序决定。

## 文档职责与交接

项目采用中文或其他现有布局时，`.ai-memory/layout.json` 可以指向真实入口：

```json
{
  "schema_version": 1,
  "document_root": "文档",
  "index": "文档/索引.md",
  "roles": {
    "rules": "AGENTS.md",
    "readme": "README.md",
    "status": "文档/当前状态.md",
    "architecture": "文档/架构说明.md"
  }
}
```

映射只引用项目内实际路径；不会改变宿主对 AGENTS／CLAUDE 等固定入口的读取规则。没有配置时复用文档整理命令的发现逻辑，优先沿用现有中文文档或 docs/doc/documentation 根及已有索引。有配置但损坏时报告问题，不擅自生成另一套体系。普通人工接续材料由文档索引导航，不伪造日志元数据。

运行 `handoff --root <项目> --task implement-search`，检查目标、完成部分、验证和下一步；standard 增加约束和阻塞，major 再增加影响、取舍、迁移／回退与验收。信息可以用明确章节或标签记录；不适用写清理由，只有空标题、`待补充` 等占位符不算有效内容。当前下一步来自唯一计划，旧日志里的下一步不能代替它。

检查只读当前计划及最近 10 条校验通过的日志，日志正文预算 128 KiB、内部完整响应预算 256 KiB。存在省略时返回未检查覆盖范围，不把节选中找不到的内容说成全部历史都没有。它检查本地 Markdown 引用和结构化 `verification.evidence` 中的项目相对路径是否存在；Git 提交等引用交给后续核实。

`verification` 中的命令、结果、提交和证据仍是记录者声明。检查不会运行这些命令，不会因字段齐全或文件存在就宣布业务通过。`gaps` 包括仍适用材料中缺失、部分验证、未执行和失败提示；其中 `not_run_or_partial` 表示存在 `partial`、`not_run` 或相应的未验证说明，可能同时存在较新的通过声明。

只有同任务明确的 `supersedes` 关系、完整读取且校验通过的相关日志、符合 v2 日志规范格式且唯一的验证声明，才将旧验证声明标为 `applicability=superseded`，不计入当前验证缺口。规范段须有精确的二级验证标题、唯一有效状态、说明与证据性质行；示例标题、未知或多个状态、结构歧义不能获得替代资格。旧声明及 `superseded_by` 来源保留在报告中，`status` 将其单列为历史。读取有错误、相关替代证据未读或被截断时，保守保留待核对提示；`corrects`、时间较新或没有规范验证声明都不能自动清除旧失败。多个仍适用声明中的失败也不会被另一条通过声明掩盖。

这个判断只调整保存声明的适用性，不证明新结论真实，也不自动解决普通文字之间的语义冲突。日志只存渲染后的 Markdown，无法区分逐字复制的规范验证块与原始对象生成的同样正文，因此不是输入字段来源认证。AI 仍应核对实际实现、测试证据与当前计划，明确哪些结论已验证、哪些仍待核实。

交接同时返回 `document_health`，检查已登记文档和实现依赖是否变化、缺失，以及评审之间可确定的冲突。项目级资料与当前任务的评审适用；其他任务的依赖不会混入。存在变化时沿给出的路径核对原文和实现，不能只更新哈希消除提示；没有登记快照不表示所有文档已核对。可单独运行 `health` 查看完整报告，具体登记与替代方式见[文档核对](health.md)。
