# 文档与实现的评审核对

在继续任务、交接、实现变化可能影响文档，或用户要求核对资料时使用。AI 负责阅读和判断，脚本负责记住当时的文件依据、发现后续变化。不要让用户逐项填写路径；从本次实际阅读的文档、代码、规格和测试结果中整理清单。

## 先核对，再登记

1. 运行 `health`，读取返回的变更、冲突和原始文件。没有快照只表示没有评审依据，不能称为“文档与代码一致”。
2. 阅读相关文档、实现和证据，说明哪些内容仍适用、哪些需要更新；需要运行测试时按当前任务授权执行，健康检查自身不运行项目命令。
3. 实际完成核对后，生成评审清单并运行 `review-docs`。这是记录评审依据，不是文档移动、任务完成或长期规则批准；已经授权的记录无需再要求用户逐项确认。
4. 同一文档有旧评审时，先阅读其 `evidence.json`。只有确实替代旧依据，才填写该文档的 `supersedes`。默认不替代，不能因为时间更晚或文件名更新就选择权威。

```sh
python -X utf8 -B scripts/ai_memory.py health --root /project --task checkout --max-bytes 16384
python -X utf8 -B scripts/ai_memory.py review-docs --root /project --file /tmp/评审清单.json
```

清单示例（`task_id` 可省略，省略时属于项目通用文档）：

```json
{
  "schema_version": 1,
  "review_id": "checkout-docs-20261015",
  "task_id": "checkout",
  "summary": "已对照结算实现和退款测试核对说明；修正退款限制，现有结果与文档相符。",
  "documents": [
    {
      "path": "文档/结算说明.md",
      "dependencies": ["src/checkout.py", "tests/test_checkout.py", "文档/验收/结算结果.md"],
      "supersedes": ["checkout-docs-previous"]
    }
  ]
}
```

第一次登记时省略 `supersedes`，或填空数组。文档的依赖可以包括代码、配置、其他文档和本地验证结果。仅登记测试代码不能证明测试实际执行；摘要仍是调用者声明。没有依赖时只跟踪文档自身，并提示覆盖不足。每批最多 256 份文档，每份最多 128 个依赖；摘要最多 8 KiB，清单和快照最多 1 MiB。路径必须属于当前项目，拒绝跨项目、符号链接、junction、内部状态和凭据文件。

快照写入 `.ai-memory/reviews/<review_id>/evidence.json`，包含项目身份、可选任务归属、评审摘要、文档及依赖 SHA-256。使用既有项目写锁，逐文件读后再核对、原子发布快照；不改文档、分类清单、任务状态和历史记录。评审 ID 必须全新，不能覆盖整理提案、旧快照或遗留封印。它记录调用者已经核对的声明，脚本不能独立证明已经阅读或业务通过。

文档正常编辑后，AI 阅读当前内容并建立有效的新评审，即可解除这部分内容过期提示，不必为了刷新哈希重新整理整个目录。旧分类清单继续保留，报告会将对应旧哈希提示降为 `classification_review_pending`：内容已核对，但用途和分类还可在后续整理时复核。存在未解决的评审分支时不作这种降级；依赖文件的变化继续单独提示。

## 读取健康报告

| 字段 | 含义 |
|---|---|
| `changes` | 已登记文件的内容变化或丢失，是重新核对的线索。包含文档路径、依赖路径、原哈希和当前哈希。 |
| `conflicts` | 明确的结构问题：不同评审分支未建立替代关系、替代关系缺失或成环、任务状态来源重复或并存。不能把普通措辞差异猜成确定冲突。 |
| `errors` | 损坏元数据、跨项目身份、不安全路径或无法读取等核验失败。有效的其他评审仍继续检查。 |
| `warnings` | 未登记依赖、没有评审基线、状态未知或扫描达到限额等覆盖提示。 |
| `needs_attention` | 存在变更、冲突或错误。退出码为 0 也可能需要复核。 |
| `checked_counts` / `coverage` | 实际检查数量和覆盖范围；仅核对已登记资料，未登记文件不能自动获得一致性结论。 |
| `total_counts` / `omitted_counts` | 截断前总数和省略数。`output_truncated` 为真时，提高 `--max-bytes` 查看完整条目。 |
| `scan_complete` | 是否完成既定范围的读取；输出截断和读取未完成分别报告。 |

`health --task checkout` 检查项目通用评审和该任务的评审、状态；排除其他任务的评审内容。已有文档分类清单是项目级依据，始终核对。未指定任务时检查全部任务。未登记项目只读返回覆盖不足，不初始化项目，也不创建目录。评审目录最多扫描 2048 个，达到上限明确标记未完成。

退出码：`0` 表示检查已完成，可能仍有变更或冲突；`1` 表示元数据/读取错误或扫描未完成；`2` 表示参数或清单输入无效。自动化应结合 `needs_attention` 和完整计数判断，不应仅看退出码。`checks_passed` 仅表示没有结构冲突或读取错误；`business_validation` 始终为 `not_performed`。

## 更新、移动和回滚

新评审只替代清单中显式列出的旧评审，而且必须属于同一任务、同一文档。旧评审中本轮未重新核对的其他文档保持有效。存在两个不同评审依据且未建立替代关系时，保留双方并报告，不按修改时间选择一方。AI 核对完双方后可新建评审，明确列出要替代的两个 ID。

正常整理移动复用已应用文档清单的 `source` 和 `original_paths`。快照保留当时路径及可追溯的文档身份，检查时跟随当前分类清单解析位置；正文因引用修复而变化时仍提示复核。新位置的评审可显式替代同身份的旧评审，不重写历史快照。回滚后根据恢复的清单回到原路径；依据有变化则再次提示。多个当前文档声称同一原路径时拒绝猜测。

首次整理的回滚可能连分类清单一起撤销。快照会保留相关整理评审 ID；检查可根据同项目的完整回滚回执、提案封印和明确的原路径/目标路径恢复对应关系。不能证实对应关系时继续保留缺失提示，并附上 `original_path_hint`，由 AI 核对；不会仅凭旧路径仍存在就自动认定是同一份内容。

未由整理清单记录的手动重命名会报告缺失。AI 应核对真实迁移后通过文档整理流程补充可追溯映射，或者建立新评审并保留旧缺失提示等待处理；不要仅凭相似文件名自动绑定。对未登记为文档的代码文件移动同样需要重新核对依赖路径。

## 与其他检查配合

`health` 不重复全量读取日志正文，不重跑测试，不自动刷新哈希以清除提示。日志的项目身份、正文完整性和 `corrects` / `supersedes` 关系继续由 `audit` / `resume` 核验；文档链接和整理状态使用 `check`。交接中的健康摘要是辅助线索，AI 仍要阅读当前任务、适用范围和证据原文。
