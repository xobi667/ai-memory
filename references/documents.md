# 已有文档的识别与整理

先读内容，再按项目职责归位。以下批量流程用于需要分类清单、引用修复和可恢复移动的任务；轻量交接的小范围文字更新直接编辑原文，不为此生成结构化配置。脚本提供盘点、校验和可恢复的文件操作；用途、取舍和冲突判断由 AI 根据真实正文填写，不从文件名猜测。用户已有授权覆盖具体整理方案时直接沿用，不逐个文件重新询问。

整理阶段的日志引用稳定的分类清单或已生成的 `.ai-memory/reviews/<id>/proposal.json`；最终位置确定后再引用归位文件。提前把待移动路径写进不可变 journal，会形成必须保留的历史引用并阻止移动。若已有此类历史引用，保留文件原位、登记用途并补导航；不要为了整理删除日志或修改旧日志校验值。

## 1. 盘点与理解

从实际技能目录执行，示例中的 `<项目目录>` 和 `<分类清单>` 替换为真实路径：

```text
python scripts/ai_memory.py inspect --root <项目目录> --documents
```

输出文档路径、格式、字节数、SHA-256、保护原因、旧分类是否仍适用，以及 `pending`、`unreviewed_count`、`scan_complete`、`skipped` 和 `errors`。扫描不修改文件；`scan_complete` 仅代表声明范围内没有扫描错误，不代表全部内容已阅读或分类。

- 阅读新增或正文哈希已变化的 Markdown；未变化且已分类的文档可复用既有判断。结合引用、代码和当前任务确认职责、当前/历史状态、所属模块与依据。
- PDF、Word、表格、图片等先登记位置、来源及关联；脚本不解析二进制正文。宿主已有可靠的本地文本提取、表格或视觉工具，且任务需要正文时，可按需读取再分类；记录原文件与页码、工作表/区域等依据，以及缺页、公式、扫描质量或视觉识别等局限。未读部分写入 `uncertainty`，不把文件名或提取成功当作全文理解。不自动安装工具、上传文档或引入 OCR 依赖。
- `.git`、`.ai-memory`、依赖、缓存、常见凭据和独立子项目不进入正文扫描；链接和 junction 不跟随。输出逐项列出排除原因。其他格式不隐式转换成 Markdown。
- 非 UTF-8 或大于 4 MiB 的 Markdown 只登记哈希，保留原位；人工分段阅读后再决定后续方案。大型或无法读取的引用文件会阻止本批移动，防止漏改引用。
- 发现重复、互相矛盾、混合用途的文档时列出依据与处理建议。不能确定正确版本就保持原文，标记未决；不根据文件日期选择“最新真相”。脚本不自动合并、删重、拆正文或判断语义相似性。

## 2. 项目布局与中文默认值

已有明确文档目录优先。没有显式布局时依次沿用存在的 `文档/`、`docs/`、`doc/`、`documentation/`；都没有才采用 `文档/`，不会提前创建空目录。存在多个同样合理的根目录时，AI 先从现有入口和用途确认归属，再写明布局。

对于自定义项目，在 `.ai-memory/layout.json` 保存最小职责映射；只填真实存在或本次明确需要建立的入口：

```json
{
  "schema_version": 1,
  "document_root": "项目资料",
  "index": "项目资料/资料目录.md",
  "roles": {
    "rules": "AGENTS.md",
    "readme": "README.md",
    "status": "项目资料/当前进度.md",
    "architecture": "项目资料/系统设计.md"
  }
}
```

所有路径相对当前项目，禁止越界、链接、设备名、敏感或内部状态目录。`roles` 允许省略不需要的职责；同一份任务当前进度仍以唯一计划为准，不为布局再创建一套状态。索引不能与任一角色入口使用同一文件。

现有有意义的文件名保留。需要新建人类阅读文件时优先使用清楚的中文名，由 AI 在清单的 `target` 给出。无法判断用途的 Markdown，指定 `role: "unknown"`、`target: null`，归入实际文档根下的 `待分类/`，保留原文件名及未知原因。若同名冲突则停止提案，AI 根据来源提出可辨认的中文名，绝不覆盖。非 Markdown 附件只登记，保持原位置。

`AGENTS.md`、嵌套规则、`CLAUDE.md`、`README.md`、`SKILL.md`、框架拥有的计划与配置、范围登记的活动计划、布局角色入口和索引保留原位。受管理 journal 日志同时保持原始字节，不通过整理改写历史。普通人工工作记录可以进入清单和索引，不添加伪造的事件头或校验元数据。

## 3. 由 AI 提交分类清单

将完整或增量分类写入普通 JSON 文件。建议放在项目外的临时目录，或使用明确的工作稿路径；清单自身不会当作应用代码引用。

```json
{
  "schema_version": 1,
  "documents": [
    {
      "source": "零散设计.md",
      "purpose": "同步模块的离线冲突处理设计与取舍",
      "role": "design",
      "state": "current",
      "target": "文档/设计/同步冲突设计.md",
      "reason": "已阅读正文及调用方，属于同步模块设计；当前实现仍采用此方案",
      "uncertainty": null
    },
    {
      "source": "未说明笔记.md",
      "purpose": "用途尚未确定，保留原文待核查",
      "role": "unknown",
      "state": "unknown",
      "target": null,
      "reason": "内容没有项目或模块标识，现有入口也未引用",
      "uncertainty": "需要确认来源及是否仍适用"
    },
    {
      "source": "附件/外部报告.pdf",
      "purpose": "同步能力的外部测试报告；关联同步冲突设计",
      "role": "evidence",
      "state": "historical",
      "target": null,
      "reason": "已核对报告来源和对应测试日期",
      "uncertainty": null
    }
  ]
}
```

`purpose`、`role`、`state`、`reason` 为非空文本，`uncertainty` 为文本或 null。`role`、`state` 可使用项目已有词汇；脚本仅对 `unknown` 使用待分类默认目录，不根据标签自行创造分类。其他角色的 `target: null` 表示保留原位。可选 `sha256` 填写盘点时的哈希，防止阅读后内容已变化却继续提交旧分类。

允许部分提交；未提交项继续列为未阅读，已有未变项保留分类，已变化的旧分类标记需要重读。不能把 `source_modified: false`、`scan_complete: true` 或没有脚本错误写成“已经全部理解并整理”。

## 4. 提案、应用和回滚

```text
python scripts/ai_memory.py propose-organize --root <项目目录> --id docs-001 --file <分类清单> --reason "按用途整理并修复引用"
python scripts/ai_memory.py apply-review --root <项目目录> --id docs-001 --confirmed --confirmation "用户已批准本批具体整理方案"
python scripts/ai_memory.py rollback-review --root <项目目录> --id docs-001 --confirmed --confirmation "用户要求恢复本批整理前状态"
python scripts/ai_memory.py check --root <项目目录>
```

提案保存到 `.ai-memory/reviews/<id>/proposal.json`，其中 `kind` 为 `organize`。提交前完整展示移动、引用改动、无法处理项、受影响文件、原文备份和暂存替换稿。备份与暂存文件按原始字节保存，并用封存哈希验证；建立提案不改变源文档。

应用时统一持有项目写锁，检查项目身份、布局和任务计划映射、所有受影响文件及引用文件哈希、文件集合、路径边界、目标冲突、备份和暂存稿。普通内联链接、图片、引用式链接的入链与出链会一并调整，支持中文、空格、括号、锚点及查询参数；远程链接和代码正文不改写。附件原位，移动的 Markdown 使用新的相对路径继续引用它们。

HTML、wiki、代码/配置、站点根路径的引用不能可靠改写时，相关文件保留原位，提案的 `blocked` 说明依据。移动文档自身带有此类本地出链时也保留原位。动态生成的链接、站点路由和外部系统的引用无法完全静态验证，AI 必须结合项目规则核对，不能承诺全网链接自动修复。

相对链接越出项目目录时，保留源文档原位并报告，不读取或修改项目外文件。路径匹配遵循操作系统：Windows 处理大小写不同的等价引用，POSIX 保留大小写区别，不把两份不同文件合并。

索引只维护 `<!-- ai-memory:documents:start -->` 到 `<!-- ai-memory:documents:end -->` 区域，其他人工正文按原字节保留；必要的路径引用调整会列入提案。无标记时追加一个区域；标记缺损、重复或倒置时停止，不猜测替换范围。索引只记录用途和位置，不复制正文或另一套当前进度。

文档清单 `.ai-memory/documents.json` 保存用途、理由、原路径、现路径、未决事项和分类依据哈希；它是分类的主要机器记录，索引从清单生成。`check` 校验映射入口、清单与本地链接，不声称验证业务事实或语义正确性。

多文件应用先发布新位置及引用，再删除已有备份的旧路径；每一步单独原子写入，并更新 `batch-receipt.json`。**整个批次并不保证同时原子可见**，中途其他读者可能看见过渡状态。中断后重复同一应用命令即可继续；也可回滚到所有原始字节。回滚先恢复旧路径，再撤销新位置，允许回滚本身中断后继续。没有递归删除，可能留下空目录；这些目录不会影响内容恢复。

发现人工编辑或不符合预期的文件状态时，应用及回滚均拒绝覆盖；保留现场，读取差异后创建新方案。应用后新增引用文件、未参与本批的引用文件变化，或布局与活动计划映射变化，也会阻止回滚，避免删除仍被新工作引用的目标；先处理新增引用，再审阅恢复方案。已完整应用且无变化时重试幂等；已回滚提案不能再次应用，需新建 ID。提案创建本身中断而没有完整封存时保留残留备份，使用新 ID 重新提案，不覆盖残留证据。
