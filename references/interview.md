# 任务范围与必要提问

先理解用户要保存或继续的任务，再选择合适记录方式。记录范围来自当前任务的真实指令；预设只提供建议。用户或项目明确要求每任务先确认时，遵守该偏好。

## 先读，只有缺口才问

1. 定位项目及适用规则，读已有交接、当前状态和相关实现；结构化项目再读任务范围。只读 `inspect` 可辅助盘点，轻量交接无需脚本。
2. 用户明确要求本技能记录、接入、继续，或已授权具体整理时，依据该指令直接执行并保存当前任务范围。不为 `small / standard / major`、字段或命名再要求选择。
3. 同一任务沿用已有授权；新任务须有该任务的实际授权依据，不能只靠旧 scope 或预设。目标、影响范围或权限仍有实质不明时，把缺口集中问一次；已确定部分继续工作。

例如用户只说“把项目都整理好”，而项目中有需保留的历史与不相关目录，可先盘点并提出具体范围，再补问是否包含这些目录。用户已明确要求“把这些 Markdown 按用途归位并修复链接”，则不为同一批文件逐项询问。版本来源、构建命令等可查证事实先读配置。

## 内部记录预设

下表只用于结构化记录；轻量交接维护一份普通 Markdown，不需要 scope 或档位。

| 特征 | 档位 | 记录重点 |
|---|---|---|
| 局部小改 | `small` | 改动、实际验证、下一步；有坑再补，无需空计划 |
| 一般功能或排查 | `standard` | 活动计划、增量记录、失败原因、修复与回归证据 |
| 跨模块、接口、架构或发布机制变化 | `major` | 设计取舍、影响范围、必要迁移/回退、验收与规则候选 |

按影响面选择，不按文件数。可选字段为 `changed / pitfall / fix / verification / next / long_term_candidates`，通常保留改动、验证和下一步。已有规划工具时沿用其计划，同一任务状态只维护一处。

按任务补充必要的版本、构建、产物、数据来源或部署信息；不要求用户选择一串内部参数。AI 采用的默认项可简要告知，不能写成用户逐项选过。

## 保存授权依据

轻量交接可在正文简记本任务目标和边界，无需生成确认文件。结构化路线在 `scope.confirmation_summary` 中引用或准确概括实际指令，并区分用户要求、补充约束与 AI 推荐。例如，只有用户实际说过“记录这次登录恢复修复，之后接着做”时，才可写：

> 用户要求“记录这次登录恢复修复，之后接着做”；本任务覆盖现有客户端和鉴权接口。AI 根据影响面采用 standard 记录并沿用现有计划；用户未逐项选择档位和字段。

这份依据只覆盖当前任务，不是跨任务永久授权。`--confirmed` 声明真实依据已存在，不替代或伪造第二次答复；字段和命令见[记录流程](lifecycle.md)。

项目常用模块、档位与字段可通过 `preset` 保存为推荐。`requires_task_confirmation` 保持兼容，表示每个任务都需要实际授权依据；默认值不是用户的答复，也不要求已有明确指令时再问一遍。明确的“每任务先问”偏好仍须执行。

范围保存后，从现有状态入口或记忆索引链接范围和活动计划。`task` 只在确需新计划时使用，保留入口人工正文；入口缺失、标记异常或预算不足时按返回项补齐。已有框架计划直接链接原文件。会话任务绑定及多任务选择见[工作流](workflow.md)。
